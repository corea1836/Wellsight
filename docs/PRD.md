# PRD: Wellsight

## 목표
건강검진 결과지를 쉽게 해석해 주고, 그 결과를 매일의 건강행동과 주간·월간 리뷰로 이어지게 한다.

## 문제
- 매년 결과지를 받아도 수치·참고치·설명을 하나씩 대조하기 어렵다
- 알고 있는 고질적인 문제가 생활 습관으로 이어지지 않는다
- 추가 검사(간수치, 요소 등)를 받으면 무엇을 해야 할지 더 모른다

## 사용자
- 대상: 공개 B2C. 첫 사용자는 본인이다. P4 공개 전까지는 허용 이메일 목록에 있는 사용자만 쓸 수 있다
- 핵심 페르소나: 정상B·경계 판정을 받았지만 약물치료 전인 성인
- 가입 연령: 19세 이상. 출생연도만 받으므로 연 나이(올해 − 출생연도 ≥ 19)로 판단한다

## 핵심 기능
흐름은 해석이 진입점이고, 관리 목표를 거쳐 일·주·월 건강행동 루프로 이어진다. 화면 흐름과 시나리오는 `docs/USER_FLOW.md`에 있다.

1. **결과지 해석**
   - PDF·사진을 올리면 AI가 항목을 추출하고 항목군으로 분류한다. 사용자는 표 한 화면에서 의심 항목만 확인하고 '모두 맞음'을 누른다. 확인된 값만 저장하고 원본은 저장하지 않는다
   - 범위: 국가검진 일반검진 항목이 표준이다. 추가 수치 검사(간수치·요소 등)도 항목군으로 분류해 해석하고 건강행동으로 연결한다. 영상 소견은 다루지 않는다
   - 판정: 결과지의 기관 판정·참고치를 그대로 쓰고, 없으면 「건강검진 실시기준」 별표4를 따른다. 추가 검사는 결과지 참고치로 판정한다. AI는 판정을 바꾸지 않는다
   - 연도별 추이를 보여준다
   - AI 해석: 값을 저장하면 자동으로 1회 생성한다. 쉬운 설명, 이전 검진 대비 변화, 이전 검진 이후의 습관 실천 회고를 담는다. 생성된 해석은 저장해서 다시 쓴다
   - 판정별 분기
     - 위급 수치(검진값·자가측정): 맨 위에 '가능한 빨리 진료' 안내
     - 모두 정상A: 유지 습관 1~2개
     - 정상B·경계: 관리 목표 제안
     - 질환의심·유질환자: 맨 위에 의료기관 상담 권장 + 생활습관 목표
2. **목표 설정**: 관리 목표는 최대 3개, 하루 습관은 최대 3개다. 습관은 검수된 습관 라이브러리에서 고르고 AI가 개인화한다. 지역은 시·도(17개) 단위로 설정한다
3. **오늘의 건강행동(매일)**: 날씨·미세먼지에 맞춘 습관을 체크하고(다음 날까지 소급 가능) 식단을 기록한다. 알림은 없고 사용자가 직접 방문한다
4. **식단**
   - 입력: 사진(Pro. AI가 음식명·양을 인식하고 사용자가 수정) 또는 음식명 검색 직접 입력
   - 계산: 식약처 식품영양성분 DB로 계산한다. DB에 없으면 유사 항목으로 계산하고 '추정치'로 표시한다
   - 관리 목표와 연결된 영양소(혈압→나트륨, 혈당→당류, 지질→포화지방)만 강조하고 주간 리뷰에 반영한다
5. **리뷰**
   - 주간 달성률: 달력 주(월~일) 기준이며 streak는 없다
   - 월간 자가측정: 체중·허리둘레·혈압과 지난 측정 대비 변화
   - AI 주간 리뷰: 마지막 주간 리뷰로부터 7일이 지나면 생성 버튼을 활성화한다. 계획 조정을 제안한다
   - AI 월간 회고: 마지막 월간 회고로부터 30일이 지나면 생성 버튼을 활성화한다
   - AI 리뷰·회고는 자동으로 생성하지 않는다. 생성 당시 기록을 기준으로 저장·유지하고 '○월 ○일 기록 기준'을 표시한다
6. **랜딩**: 가입 전에 가상 데이터로 만든 샘플 화면을 보여줘서, 어떤 서비스인지 바로 알 수 있게 한다

## 웰니스 경계
- 금지: 질환명 단정, 질환 가능성, 발병위험도, 신체나이, 약물·치료 조언
- 면책 고지를 표시한다

## 성공 기준
- 본인 테스트: 8주 동안 주간 달성률 70% 이상 + 월간 자가측정 유지
- 공개 후: 가입 4주 차 주간 활성 비율

## MVP 제외 사항
- 웨어러블·건강 앱 연동, 가족 구성원 관리, 검진 결과 자동 조회 연동(마이데이터·조회 대행 API)
- 네이티브 앱, 카카오 로그인, 알림·PWA(반응형 웹만 만든다)
- 영상 소견 해석, 식별정보 마스킹, 결과지 원본 보관
- 동의 버전 관리·재동의·철회 흐름(MVP는 체크 2개만 두고, 철회는 탈퇴로 처리한다)
- 분당 요청 제한
- 개인정보·법령 관련 추가 검토와 세부 설계(P4 준비 단계에서 다룬다)

## 개발 단계
개발 단계는 P0~P4로, 사용자 여정 단계는 ①~⑤로 표기한다.

| 단계 | 범위 |
|---|---|
| P0 | 저장소 셋업(모노레포, harness 정합) + 랜딩 샘플 화면 + Auth(허용 이메일 제한) + 프로필·동의 |
| P1 | 결과지 업로드·추출·확인·해석·추이·위급 수치 안내 |
| P2 | 습관 라이브러리 + 목표·습관·지역 설정 + 오늘의 건강행동(날씨) + 주간·월간 리뷰 → 본인 8주 테스트 시작 |
| P3 | 식단(사진·직접 입력) |
| P4 | 공개 출시 |

## 공개 출시 조건 (P4)
아래가 모두 갖춰져야 공개한다.
- 허용 이메일 제한 해제
- 추출 함수를 서버 내장 모델로 교체 (모델 선정 TBD)
- 동의 관리 흐름(버전 관리·재동의·철회)
- Vercel·Supabase Pro 전환(약 $45/월, 백업 확인)
- 법적 체크리스트: 처리방침, 개인정보 보호책임자, 안전성 확보조치, 전문가 확인
- Polar 결제 연동
